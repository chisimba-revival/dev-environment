## Required adapter behaviour

- Render a `<textarea>` with the exact field name and identifier expected by existing forms.
- Populate initial HTML content without altering stored markup.
- Synchronise editor content back to the textarea before normal form submission.
- Preserve width, height, rows, columns, and toolbar options where modules use them.
- Preserve raw-text fallback behaviour.
- Preserve multiple editors on one page.
- Avoid global JavaScript collisions.
- Keep file/image/link integration behind a Chisimba-owned adapter.
- Fail safely to a textarea if the editor JavaScript cannot load.

## Migration strategy

1. Add a new editor adapter without deleting CKEditor 3.
2. Add a new `SYSTEM_EDITOR` value for the modern adapter.
3. Test contextcontent first, then representative modules.
4. Keep `ckeditor` available for immediate rollback during testing.
5. Remove CKEditor 3 only after regression testing is complete.
